# SimMusic

网站：https://simmc-music.github.io/

阿里云后端：https://121.40.158.251:1145 。实际部署与维护见 [部署说明](docs/ALIYUN_DEPLOY.md)。

备用 Cloudflare：https://simmusic.simmc.workers.dev

自动部署：[GitHub Actions](https://github.com/Bocchi-The-Glock/SimMusic/actions/workflows/deploy.yml)，推送到 `main` 后运行。

Simmc 玩家 Livehouse 排班与乐曲收录网站。Google 风格的简洁浅色界面，支持桌面和手机。

## 功能

- 游客自由浏览，并可填写游戏 ID 添加整点演出。
- 顶部横向导航包含 Livehouse、音乐、艺术家、商店、我的。
- 玩家使用游戏 ID 和密码注册、登录；注册需确认密码，个人界面可编辑简介。
- Livehouse 独立主页、可分享链接、月历、节目计数及按小时分组的日程。
- Livehouse 主页上方左侧显示场地信息和图片、右侧为日历，下方显示当天排班；手机端纵向排列。
- 个人主页支持上传、更换和移除头像；艺术家目录同步显示该头像。Livehouse、乐曲、商店各支持一张可选封面图，创建时可上传，所有者和管理员可更换或移除；Starry 的图片由管理员管理。
- 图片在浏览器中自动缩放并重新编码，保存前验证不超过 100,000 字节（100 KB）。原始文件不设文件大小门槛，需为浏览器能正常解码的图片；压缩失败不会上传原图。后端再次校验大小、格式及权限，图片保存在 R2。
- 未上传图片时使用稳定的随机底色与文字，不生成或上传默认图片，也不占用 R2 存储。头像显示首个可见字符，Livehouse 和商店封面最多 3 行，每行最多 8 个可见字符（空格计入），优先保留完整单词，超过 8 字的单词拆行；乐曲封面最多 10 个字符（包含空格），优先保留完整单词，只有首个词超长时截断。无空格中文按前 10 个字符显示，Unicode 字符不会从中间截断。图片加载失败时也回退到文字封面。底色与四种本地字体栈均按实体标识固定选择，刷新不变；根据文字实际宽度及容器自动调整字号，不加载外部字体。
- Livehouse 和商店的附近港口均为选填，不填写时不展示空信息行。
- “我的”页面集中展示个人主页、自己的音乐、商店、Livehouse 和红心收藏。
- 登录玩家可收藏或取消收藏乐曲，卡片与详情显示红心数量；每个账号每首乐曲最多一次，收藏保存在数据库。
- 乐曲作者和管理员可编辑乐曲全部内容，管理员编辑不会改变作品归属。
- 普通玩家只能编辑、删除自己的场地；管理员可管理场地。Starry Livehouse 在服务端固定保护，无法通过任何应用接口删除。
- 乐曲按音乐类型筛选、按价格排序。数字价格必须大于 0，亦可选择定制。
- 上传过乐曲的注册玩家自动进入艺术家目录，展示游戏 ID、作品数及简介。
- 乐曲与商店为多对多关系，允许暂无商店。输入店名联想补全；确认已有商店，或在独立窗口创建新商店后自动选入乐曲。
- 商店目录支持创建、编辑和删除。创建者只能管理自己的商店，管理员可管理全部商店；删除商店保留乐曲。升级前没有创建者记录的商店仅由管理员管理。
- 内置 52 种音乐类型，只有管理员可新增类型。
- Cloudflare D1 持久化，服务端权限校验；密码 PBKDF2 哈希，会话 HttpOnly Cookie。

## 本地开发与部署

详细步骤见 [Cloudflare 部署说明](docs/CLOUDFLARE_DEPLOY.md)。本仓库独立部署到你自己的 Cloudflare，前后端使用同一个 Worker，数据使用 D1，图片使用私有 R2。

```powershell
npm ci
npm run db:migrate:local
npm run dev
```

发布前执行 `npm run check`、`npm test` 和 `npm run build`。首次配置 Cloudflare 账号、数据库、R2 与 GitHub Secrets 后，推送到 `main` 自动部署。单独保存本地文件不会发布。实际部署配置 `wrangler.production.json`、凭据、图片和本地数据库均不进入仓库。

## 数据与时间

创建、修改和删除在服务器确认成功后立即更新当前页面，其余数据在后台同步。旧的同步请求不能覆盖后续操作的结果；同步失败时保留已确认的数据，并提供重试入口。写入失败保留表单内容，不自动重发创建请求。

会话、用户、简介与头像通过一次联表查询读取；全站状态通过一次数据库批处理获取。旧图片在关联更新成功后通过服务器后台任务清理，不阻塞操作响应。

演出时间采用北京时间（UTC+8），只允许 0–23 时的整点。同一时间按服务器生成的递增节目 ID 排列。登录玩家 ID 由服务器会话确定，不能通过请求字段冒用其他玩家身份。游客填写的 ID 仅用于节目署名，不授予该游戏账号的权限。

默认只有 Starry Livehouse：坐标 `(-6374, 67, 8820)`，附近港口 `凯撒岛中心港`，所有者 `Bocchi_TheGlock`。正式数据没有填充示例演出或示例乐曲。

## 图片与权限验证

`node --test lib/cover-placeholder.test.mjs lib/client-state-check.test.mjs` 检查封面截字和保存后的状态同步。`lib/server/profile-shop-images-check.mjs` 检查头像、商店封面的上传/移除、权限、事务与大小边界；`lib/server/music-favorites-check.mjs` 检查收藏幂等、账号隔离、乐曲编辑权限、可选港口和场地保护；具体运行方式以脚本说明为准。

品牌使用 SimMusic。旧的会话 Cookie 名称保留兼容，现有用户和已上传图片不会因改名失效。

封面排版更新：中文统一优先使用微软雅黑；英文常规每行10字符，超长单词按实际宽度尝试完整显示，放不下时再拆行。音乐默认封面文字缩小20%。小节数选填，未填写内部以0保存且界面隐藏。
